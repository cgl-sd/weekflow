# Weekflow 企业级发布验收基线

本清单是正式发布的唯一验收基线。代码审查发现的问题必须映射到编号并由自动测试、构建检查或人工系统验收给出证据。

## P0 数据安全与可发布性

- ER-001：异常退出计时必须由用户确认是否计入离线时长。
- ER-002：恢复只接受枚举且通过 SQLite 完整性校验的备份，并先保留当前库安全副本。
- ER-003：重试和恢复必须在同一进程内释放并重建仓库，不能通过重复启动规避错误。
- ER-004：所有已知不稳定回归必须可重复通过。
- ER-005：正式应用和 DMG 必须使用 Developer ID、Hardened Runtime、公证与票据装订。
- ER-006：应用包、ZIP、DMG 和 Git 跟踪文件不得包含 `.data`、用户数据库、备份或恢复副本。

## P1 完整性、安全与兼容性

- ER-007～009：备份失败对用户可见；备份、安全副本和内部变更历史均有容量上限。
- ER-010：同步桥超时后不得发生延迟写入。
- ER-011～012：完整归档覆盖全部业务实体；导入前校验、备份、单事务替换并经重启验证。
- ER-013：Debug 只用项目 `.data`，Release 只用沙盒 Application Support。
- ER-014：复合写入原子提交，失败进入保护模式且不覆盖原文件。
- ER-015：冻结历史 schema、迁移指纹和历史数据库 fixture 必须通过。
- ER-016：更新检查遵循 SemVer（含预发布优先级）并限制受信任 HTTPS 地址和响应大小。
- ER-017：权限仅限沙盒、网络客户端和用户选择文件读写。
- ER-018～019：磁盘满、只读、锁定故障回滚；数据目录 0700、数据文件 0600。

## P2 架构、稳定性与效率

- ER-020～021、027：业务日历由 Store/Environment 注入，多窗口命令只作用于活动窗口，不依赖可漂移的裸全局状态。
- ER-022：内部事务历史有时间与数量上限；用户正文、评论和归档不得因清理策略丢失。
- ER-023～025、029：启动预加载不阻塞主线程；一万任务冷启动和单实体编辑满足基准测试阈值。
- ER-024：退出前先结算计时，再以完整应用快照单事务保存。
- ER-026：诊断支持文件提供数据库计数、历史大小和可清理记录数，不读取业务正文。
- ER-028：系统滚动条在重复创建和滚动后保持预留、可见和对齐。
- ER-030：窗口、Store、全局快捷键、状态栏和观察者均有明确释放路径。

## P3 隐私、体验与发布运营

- ER-031～032：仓库和应用内说明明确本地存储、网络边界和最小 entitlement。
- ER-033～034：可导出脱敏诊断；日志和故障标记不包含用户主目录绝对路径或业务正文。
- ER-035～036：关键控件具备可访问名称/值；浅色、深色和“减少动态效果”可用。
- ER-037～038：每版包含发布说明、ZIP/DMG SHA-256 和构建清单。
- ER-039：保留可执行的安装升级与回滚说明。
- ER-040：列出全部运行时依赖及许可证；无第三方依赖时也须明确声明。
- ER-041：构建清单固定源码提交、版本、构建号、Swift、Xcode 和最低系统；签名时间戳导致二进制哈希不同属于预期且必须记录。
- ER-042：首次安装、覆盖安装、历史版本升级、Debug/Release 隔离、损坏库、只读磁盘、ZIP 和 DMG 均纳入发布矩阵。

## 自动验收命令

```bash
cd 01_workspace && swift test
cd .. && ./script/build_and_run.sh --verify
./script/build_and_run.sh --package
WEEKFLOW_DEVELOPER_ID='Developer ID Application: …' \
WEEKFLOW_NOTARY_PROFILE='weekflow-notary' \
./script/build_and_run.sh --release
```

正式 `--release` 仅允许在干净工作树和精确的 `v<版本>` Git 标签上运行。发布后还必须在另一台未授权的 Mac 上执行安装矩阵中的 Gatekeeper 与升级验收。
