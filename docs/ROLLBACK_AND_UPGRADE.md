# 安装、升级与回滚

## 发布前安装矩阵

每个正式版本必须在受支持的最低系统 macOS 14 和当前最新稳定 macOS 上完成以下场景：

| 场景 | 验收结果 |
|---|---|
| 无历史数据的首次安装 | 创建正式版沙盒数据目录，启动无示例业务数据 |
| 从 v0.7.0 升级 | 原目标、任务、规划和日期语义保持一致 |
| 从 v0.7.1 升级 | 原数据可读写，首次启动备份通过完整性校验 |
| 覆盖安装同版本 | 不重置数据，不重复迁移 |
| Debug 与 Release 同时存在 | 分别使用项目 `.data` 与正式沙盒，互不读取 |
| 数据库损坏 | 进入只读保护界面，只显示校验通过的备份 |
| 磁盘只读或空间不足 | 当前事务回滚，暂停后续保存并显示错误 |
| ZIP 与 DMG 安装 | Gatekeeper 验证通过，应用和 DMG 均有公证票据 |

## 回滚步骤

1. 退出 Weekflow，保留当前 `Backups` 和 `RestoreSafety`，不要直接覆盖数据库文件。
2. 保存当前版本的完整数据归档与诊断支持文件。
3. 安装上一个已公证版本；如果旧版本不能读取新数据格式，不要反复启动。
4. 优先重新安装新版本并从其恢复界面选择升级前备份。只有格式明确兼容时，才在旧版本中导入归档。
5. 发布撤回时保留 Git 标签、DMG、ZIP、`SHA256SUMS`、`BUILD-MANIFEST.json` 和发布说明，以便复核。

数据库格式升级必须新增冻结 schema 和显式迁移阶段，不允许原地修改既有冻结 schema。迁移失败时原数据库字节必须保持不变，并进入保护模式。
